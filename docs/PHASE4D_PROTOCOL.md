# Phase 4D frozen evaluation protocol v1

This evaluation-first checkpoint precedes 4C at the user's explicit request. The generator extends `evaluation/fixtures.py` through `expanded_fixtures.py`; inference, forest parameters, feature order, temporal rules and authorization policy stay unchanged. Existing fixtures and the 4B library are development data. Smoke seed17 is development exposure. Full seeds41/53/67 are selected in advance without outcome search. Each has its own training/calibration/test partitions at UTC January1–14/15–21/22–28 2026, with partition seed offsets0/1/2. There are 30 routine users per full profile (6 smoke), 20 possible endpoints and six routine apps. Per full profile, background requests are10000/5000/5000; additional scenario rows and a rejected timestamp row are counted separately. Groups may produce fewer background records than requested. Each dataset stays below50000 unique events.

The executable machine protocol is `protocol(profile)` in `evaluation/expanded.py`. Each invocation exclusively creates a new output directory and writes `protocol.json`, `PROTOCOL.md`, and `freeze.json` before generating or analyzing final data. A SHA256 and evaluator source hashes accompany the results. This is local reproducibility, not independently audited preregistration. Never overwrite an exposed or failed run; preserve it, disclose any subsequent defect/fix and change protocol/generator versions for semantic changes.

Four supported attacks per full seed (12 total) vary actor, endpoint, resource, positive transfer amount, delays, and episode day. Variants are compact chain, a24-minute chain spanning feature windows, direct compatible alias with independent corroborating copy, and a second temporally separate episode for the first actor. All use explicit matching sensitive resource/copy/media and active prior mount with strict order within60minutes. Interleaved background uses the same NAT IP; it cannot join actors. These remain variants of one supported chain, not new attack techniques or independent real-world samples.

Both calibration and test contain eight legitimate export cases: exact declaration, withheld declaration, expired declaration, future declaration, wrong resource scope, repeated matching declarations, shared IP without available declaration, and familiar prior resource/device/app/hour. Seven are intended to be stage-eligible; familiar activity may not become a candidate. Truth remains benign for withheld or nonmatching declarations. Operator declarations carry explicit synthetic provenance. Nine observational templates retain mount-only, access-only, missing copy, failed copy, zero bytes, wrong resource, wrong media, ambiguous identity, and out-of-window timing. In final test, missing-copy and out-of-window cases are malicious but insufficiently observable/out of scope; they are separately reported, never reclassified benign. Calibration versions are explicitly legitimate observations. Malformed authorization context rejection is covered by regression tests; valid nonmatching declarations are evaluated cases.

Training and calibration are explicitly declared benign. The unchanged locally fitted200-tree IsolationForest and preprocessing use frozen training history; percentiles use separate calibration windows. Native incident threshold selection is unchanged: lowest boundary>=80 meeting the proposed1% active-unit budget, with existing fallback when no useful boundary is found. Save calibration unit/sample/candidate counts, all complete scores, validation and alerts before final inference. Freeze the resulting artifact hash and thresholds in `selected-artifact.json`. Anomaly-only uses the existing99th-percentile raw calibration threshold (`higher` quantile), inclusive equality. Ties may exceed1%; record them. Cold-start or provisional windows have no score and cannot emit alarms.

Rules-only uses selected frozen baseline history without forest scoring and preserves its structural risk100/alert semantics. Hybrid uses ordinary production orchestration. Anomaly-only reuses real feature and scoring functions and emits window alarms. The optional executed diagnostic copies actual hybrid predictions, substitutes only A=0, recomputes the clipped weighted sum and decision at the same threshold, and retains structural evidence, other risk terms, authorization, scored-window availability and missing-component gates. It never enters production incident storage or becomes a selectable application mode. It measures fixed-threshold sensitivity, not an optimized alternative detector. Rules-versus-hybrid differences alone cannot isolate the model; authorization's20-point reduction is a policy effect.

Incident matching uses the existing evaluator contract: exact resolved scoped actor/endpoint, required labeled evidence in each stage and strictly ordered label constraints in selected evidence. Predictions earn at most one episode and episodes at most one prediction. The evaluator rejects oversized predictions compatible with several episodes and records eligible matches, duplicate-credit rejection, unmatched predictions and truth. Required-stage and order coverage includes validated partial/review candidates, independently of alert episode recall. Evidence validity comes from real independent source/stage/graph verification, not an unconditional badge.

All modes share the accepted, alias-resolved active user-device-day population. A UTC unit has at least one accepted observation with usable actor/device and no labeled malicious observation for that pair/day, including deliberately unobservable cases. Exact/direct effective aliases resolve before population calculation; ambiguous aliases remain separate. Selected evidence (all days it spans), or all evidence in an alarm window, implicates units. Units without candidates stay in denominators. Save pairless counts and actual common benign-unit lists. Benign false outputs per1000 accepted test observations and false-positive-unit fraction are distinct measures. Window alarms have no chain precision/recall/stage metrics. Empty denominators are null. Totals sum counts rather than average seed percentages. No independence-based confidence interval or generalization claim is made.

Measure monotonic generation/ingestion, fitting, calibration audit, per-mode inference/persistence, independent verification, evaluation and real4A no-op sensitivity/verification. One measurement per seed, fresh database/model, warm installed libraries/OS caches; host contention uncontrolled. Process resident memory is unmeasured. Three different seed timings are workload measurements, not repeated identical input trials. No batch timing establishes streaming throughput. Save all predictions, windows, isolated truth, quality, calibration, matching, case outcomes and costs. Keep runtime/private paths out of the compact representative report. Full browser/native restart/export regression gates remain required. Replay and final submission checks remain for4C/final handoff.
