# Phase 1 decisions

- 2026-10-06: Empty repository, no working foundation to preserve. Copied the user's Downloads specification to the requested root `prompt.md`. No commits, deployment, publication, or destructive Git operations performed.
- Use Python 3.12, FastAPI/Pydantic, SQLite and React/TypeScript/Vite. Defer pandas, NumPy, scikit-learn, NetworkX, Cytoscape and Tailwind until needed; plain local CSS suffices for this basic UI. Runtime assets have no CDN dependencies.
- System `python` is a Windows Store stub. Bootstrap `.venv` with the available Codex bundled Python 3.12.14, without altering global Python. Pin installed/tested dependencies in `pyproject.toml`, generated `requirements.lock`, and frontend `package-lock.json`.
- One common field contract, four source-family adapters with explicit per-action requirements. No vendor/universal ingestion claim. UTC offset conversion preserves the original timestamp. Naive local times require operator-declared IANA zone; ambiguous/nonexistent DST times are rejected.
- Entity IDs encode trusted environment, type and raw identifier. No fuzzy merge, IP join, or implicit alias resolution. Dataset/source scopes event IDs. Reliable vendor-ID collisions with different normalized content are quarantined; content-derived IDs otherwise deduplicate exact semantic records.
- SQLite retains original uploaded bytes and all raw source rows, including rejected and duplicate rows. User filenames are metadata, not paths. SQL uses bound values. Immutable analysis metadata includes accepted event IDs, resource-context snapshot, config, cutoff, fingerprint and seed.
- Historical comparison uses only earlier UTC days for the same exact account, minimum three logins and three reads. Current-day activity cannot train itself. No persisted trained baseline or ML exists. Cold starts produce explicit warnings and no unusual-login claim.
- Collection requires a rare matching resource with an operator-supplied sensitivity label effective at read time. Log-provided approval/sensitivity text is never trusted. Phase 1 does not implement authorization suppression or contextual policies.
- One episode selects the first compatible rare-resource read and explicit copy, with prior active mount. Ordered user/endpoint groups and time-window lookup bound matching. Overlapping authentication candidates consumed through the selected episode end; distinct later episodes remain separate. Redundant copies are not multiple alerts. This is a narrow rule, not generalized attack reconstruction.
- Strict timestamps establish order; equal timestamps never establish authentication→collection→transfer or mount→copy. USB unmount at copy time conservatively invalidates mount context. Mount may occur before collection/authentication but within 60 minutes of copy.
- Phase 1 risk: `60 * supported_required_stage_fraction + 20 exact_entity_links + 20 supported_transfer`. Threshold 100 plus evidence gates. Complete=100, two-stage review=60. No calibration/probability/ML claim. Future hybrid policy belongs to Phase 2.
- Small synchronous local analyses, capped at 10,000 unique events per dataset, 5 MiB and 10,000 rows per upload, 64 KiB per record, 1,000 sensitivity labels. No background-job runner needed for this slice. No large-scale performance promise.
- UI supports fresh analyses of saved datasets; historical runs remain accessible through API/CLI. No fake model, graph, evaluation, export or counterfactual buttons. A small real browser test is included to verify this slice; submission-ready browser/export flow remains Phase 3.

- Frozen baseline requires explicit training and calibration selections and a benign-provenance declaration. Require separate environment-compatible, chronological closed-window datasets and at least 20 established windows in each. The declaration is operator trust, not an automatic guarantee that real logs are benign.
- Persist locally fitted estimator bytes, hash, exact versions, training/calibration IDs and fingerprints, feature order/transforms, seed, frozen history, alias/sensitivity snapshots and calibration scores in SQLite. Only locally created/hash-checked compatible artifacts load. The local database is trusted storage; a hash is not a defense against someone replacing both artifact and hash.

Training features reference only the selected training snapshot; calibration/test use that unchanged snapshot. Exclude cold-start/provisional windows from anomaly scoring. Explicit cutoffs retain narrower observed stage evidence without future data.
- Midrank empirical CDF of negative `score_samples` over declared benign calibration windows yields an anomaly percentile. It is rarity, not probability of compromise or exact feature attribution.
- Hybrid policy implements the prompt's proposed `50*C + 20*A + 20*L + 10*I - B`. Exact links=1, explicit time-valid account aliases=0.9; B=0 until scoped authorization in Phase 3. Impact=min(sensitive-resource transfer bytes / 1 MiB,1). Full evidence + graph gates are mandatory; incomplete candidates remain partials even with extreme anomaly scores. Below-threshold complete chains remain visible review items.
- Select a threshold >=80 on declared benign calibration user-device-day predictions against the proposed 1% budget. If no complete benign candidates exist, explicitly retain structural floor 80. If meeting the budget would conceal every available complete candidate, retain floor 80 and report failure. This is not a final production operating point; richer development attacks/benign exports are needed for useful discriminatory calibration.
- Aliases are explicit environment-scoped, time-valid direct account mappings. Different active targets/chained aliases are ambiguous and do not force joins. Source observations remain unchanged, with applied mappings snapshotted. Shared NAT/VPN context stays separate; IP graph nodes are observation-time scoped.
- Build a NetworkX MultiDiGraph and recheck required typed relations for every Phase 2 candidate before saving. Multiple edges from one event do not increase independent evidence count. Basic UI lists typed graph relations; linked graphical exploration is Phase 3.
- Generate chronological profiles in an evaluation-only package, with seeds separated across fit/calibration/test. Labels enter metric code after independent predictions; sidecars and immutable JSON metrics are saved in fresh evaluation directories. Inference modules never import evaluation helpers. Compare rules-only and hybrid on the same held-out observations; anomaly-only ablation remains Phase 4.
- Preserve small UI defaults (1,200 requested events, six users) and expose a roughly 20k/30-user CLI profile. Raise total dataset cap to 50,000 while retaining all upload limits. Validate original source files once per operation through a bounded batch, avoiding repeated full-file parses during model fitting.
