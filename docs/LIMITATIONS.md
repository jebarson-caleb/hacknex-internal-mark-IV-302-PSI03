# Honest limits after Phase 4D

- Synthetic observations test implementation, not real-world generalization. One held-out labeled episode is insufficient for strong precision/recall claims. No universal log support or hidden evaluation data access.
- Both measured modes detect the same episode with the same clean-unit false alerts. ML affects risk/ranking; additional detection value has not been demonstrated.
- Benign data provenance is an operator declaration. The app checks chronology, consistency and versions, but cannot independently prove real logs benign.
- Recorded calibration has no complete benign candidates and retains floor 80 with a warning. Zero test FPR still has an approximately 1.78% Wilson upper bound on the larger synthetic holdout.
- Frozen history and explicit telemetry are required. Cold-start/provisional windows have no forest score. Missing evidence or failed observations cannot be replaced by high risk.
- Only exact IDs or direct trusted account aliases join entities. Ambiguous, chained and expired aliases do not force joins. Device handoffs/fuzzy resolution are unsupported; shared IPs are context only.
- Without reliable source IDs, identical same-time events can be indistinguishable from duplicates. Distinct vendor IDs preserve genuinely separate repeated observations.
- One selected compatible resource per bounded episode; generalized/slow/unknown chains and adversarial evasion are outside current scope.
- Scoped authorization subtracts 20 once in hybrid; a legitimately authorized export may still alert if its score remains above threshold. Rules-only scores remain structural. Exact operator declarations are not independently verified; log self-approval never suppresses alerts.
- Synchronous local SQLite, bounded uploads and 50k-event datasets; no crash-surviving jobs, streaming/late-event guarantees or horizontal scale. The roughly 20k profile was measured; process memory was not.
- Only app-created artifacts from the trusted local database load. Hashes establish consistency, not safety of external serialized code, source authenticity or human intent.
- Local unauthenticated operator API; loopback default. Do not expose publicly. Alias/sensitivity provenance is local operator trust, snapshotted per run.
- Linked SVG graph and accessible relation list are bounded; node limit 500, candidate pages 20, API maximum 100, recent run selector 200. Older runs remain accessible by known URL/API ID. Recommendations require human review; no approval/action is claimed. Docker configuration exists but engine/build/runtime checks are blocked.
- Evidence sensitivity is an evidence-availability experiment, not causal proof, prevention, remediation or machine unlearning. Fitted material stays fixed; independent surviving observations may retain a stage. A missing child candidate has unavailable risk and does not mean safe. Matching uses episode overlap plus shared evidence and exact scoped identities/family; ambiguous correspondences are exposed.
- Sensitivity supports compatible ordinary parent runs only, maximum 100 requested exclusions/500-character note/50,000 observations. Nested branches, context editing and cutoff changes are rejected. A full source/no-op/child rerun is synchronous; duration covers validation and inference before comparison assembly/persistence, not streaming throughput or measured process memory. Policy implementation/library fingerprints deliberately reject unavailable historical implementations. Legacy parents remain reportable but require a new ordinary run for sensitivity.
- Optional narration remains unimplemented; Phase 4C retrospective replay is now implemented. Phase4D anomaly-only is an isolated CLI window-alarm comparison, not a production chain mode. Windows isolated install results remain historical; fresh Phase 4B and preserved 4A native workflow/restart checks are recorded in BUILD_STATUS. Independent second-machine/POSIX installation is unverified. Legacy runs lack frozen source-reference lists and explicit calibration status; reports disclose those as unavailable/unknown. New ordinary runs freeze all inference/history source references. Report privacy omissions require retained local material for full verification; no standalone signature/authenticity proof is supplied.
- The 4B library is curated synthetic development/regression data, not a new held-out evaluation or calibration set. Remaining alerts on declared benign cases are retained as fixture-level false positives; partial/review/absent items are not counted as false-positive alerts or verified safe endpoints. Missing declaration does not establish intent. No FPR/accuracy percentage is attached to this lab; no measured model detection improvement is claimed.
