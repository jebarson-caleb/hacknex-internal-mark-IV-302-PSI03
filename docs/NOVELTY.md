# Implemented engineering differentiators

These are project engineering features, not claims of scientific novelty, first-of-their-kind research, causal proof or judging guarantees.

## Phase 4A: evidence sensitivity

User question: **What would this detector conclude without selected supporting observations?**

`views.py` projects the parent's frozen inference membership and cutoff, removes canonical IDs including every duplicate representation, and supplies frozen context, fitted baseline and source references to the ordinary `run_analysis` pipeline. The pipeline recomputes windows, real forest scores, candidates, predicates, graphs, risk and decisions. Training/calibration remain byte-identical. Policy/module/library identities and a semantic no-op reproduction fail closed for incompatible historical parents.

`sensitivity.py` saves a child and comparison atomically with explicit lineage, exclusions, effective fingerprint, immutable artifact/context/source identities and measured validation/inference duration. Matching requires the same rule family/scoped actor/endpoint, overlapping episode time and shared evidence; ambiguity is visible. All candidates survive persistence; child ordering agrees with the retained store. The UI shows before/after stages, support, predicates, graph links, numeric terms and decision reasons, with parent/child source navigation and refresh URLs.

Acceptance evidence: `backend/tests/test_phase4a.py` covers no-op reproduction in both modes, sole-copy and mount/auth removal, duplicate provenance, independent-copy survival, changed/later episode selection, ambiguous matching, later uploads/context, fixed model/no fitting, exact removal from USB-byte features/windows/graphs, malformed/legacy/nested/policy rejection, report immutability, reopen and comparison/source/child tampering. `frontend/tests/browser/sensitivity.spec.ts` exercises actual built UI/API, narrower partial/empty output, parent return, refresh, download, CLI/API verification and tamper rejection. The native smoke script produces separately saved original/no-op/excluded/tampered exports and verifies them after restarting the real loopback server.

Limits: evidence availability is not causality or attack prevention. No incident means no incident risk, not a safe endpoint. Missing or ambiguous telemetry remains uncertain. Maximum 100 exclusions; ordinary compatible parents only. Historical implementation fingerprints are deliberately strict. This 4A feature does not introduce a new model or held-out tuning; subsequent 4C and saved 4D work is documented separately.

## Phase 4B: inspectable policy and context comparison

User question: **Which retained observations and declarations explain different or unchanged decisions?** Two ordinary analyses freeze independent authorization snapshots; a small comparison references their run/artifact/source/context identities. Context-only validation requires all other inputs and upstream computations to agree. Separate scenario comparisons list actual changed inputs and keep unmatched or ambiguous episodes explicit. Correspondence uses rule family, scoped actor/endpoint, overlapping event time and shared evidence, never list position.

The workbench exposes actual policy terms, copy-time predicates, historical eligibility, anomaly availability/percentile, threshold origin and sparse calibration. Each arm links to frozen source records, timeline/graph and existing incident reports. Synthetic truth is a separate presentation annotation after inference. Missing authorization cannot identify malicious intent; valid declarations cannot guarantee suppression. The current lab includes unchanged review decisions for repeated matching tickets and unchanged rules-only alerts on both declared benign arms. This demonstrates inspectable heuristic behavior, not scientifically novel detection, ML gain, source authentication or causal proof. Native acceptance and restart evidence is in BUILD_STATUS.

## Phase 4C: inspectable event-time emergence

Replay asks what the unchanged detector reconstructs from retained observations through T with a fixed historical baseline and captured operator context. Real cutoff reruns expose partial/complete candidates, unavailable versus closed anomaly windows, backward state, source predicates and unchanged parent findings. This is an inspectable retrospective workflow, not a novel detection algorithm, causal proof, historical analyst-knowledge reconstruction, real-time system or evidence of improved false-positive performance. The saved expanded 4D 1% target remains unmet.
